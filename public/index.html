How the score works

Every PR starts with 100 points split across five things reviewers care about. Nothing is a black box: the report shows exactly where points were lost.

CategoryPointsLoses points when…
Size30the diff is over 250 lines, or touches more than 5 files
CI25checks are failing, or the repo reports no CI at all
Tests20source code changed but no test file did
Docs15behaviour changed without a README, docs or changelog update
Commits10commit messages are things like “fix”, “wip” or “update”

Other ways to use it

  • Trends scores a repo’s last 10 merged PRs, so you can see if things are getting better.
  • A GitHub Action posts the report as a comment on every new PR.
  • A Chrome extension shows the score right on the GitHub PR page.
  • An SVG badge you can drop into a README.

Things it can’t tell you

It doesn’t read your code for bugs or judge the design. A PR can score 100 and still be wrong. Think of it as the checklist a maintainer runs through in the first minute.
